# Altair REST API

Altair exposes a read-only REST API via Supabase PostgREST for querying consultant, project, assignment, revenue, and capacity data.

## Getting Access

API keys are managed in your Supabase project. Generate a key with the appropriate RLS policies scoped to read-only access, then distribute it to trusted clients. The key grants access to all operational data visible through the anon/authenticated RLS roles.

Include the key in every request as shown below.

## Connection

| Field | Value |
|---|---|
| **Base URL** | `https://<YOUR_SUPABASE_PROJECT>.supabase.co/rest/v1` |
| **Access** | Read-only (SELECT). All writes blocked by RLS. |

**Required headers** on every request:

```
apikey: YOUR_API_KEY
Authorization: Bearer YOUR_API_KEY
```

## Query Syntax

Full reference: https://postgrest.org/en/stable/references/api/tables_views.html

### Filtering

```
?column=eq.value          -- equals
?column=neq.value         -- not equals
?column=gt.value          -- greater than
?column=gte.value         -- greater than or equal
?column=lt.value          -- less than
?column=lte.value         -- less than or equal
?column=ilike.*text*      -- case-insensitive search
?column=in.(a,b,c)        -- in list
?column=is.null           -- is null
?column=is.true           -- is true
```

### Selecting columns

```
?select=col1,col2,col3
?select=*                           -- all columns
?select=*,projects(client_name)     -- with join
```

### Sorting & pagination

```
?order=column.asc         -- ascending
?order=column.desc        -- descending
?limit=10                 -- max rows
?offset=20                -- skip rows
```

## Common Queries

### List active consultants

```
/consultants?is_active=eq.true&select=full_name,title,manager,country&order=full_name
```

### Get a project by client name

```
/projects?client_name=ilike.*acme*&select=client_name,project_name,status,sow_amount
```

### Assignments with project + consultant details

```
/assignments?select=start_date,end_date,total_hours,projects(client_name,project_name,status),consultants(full_name)&order=start_date
```

### Billable assignments in a date range

```
/assignments?select=*,projects(client_name,project_name,sow_amount,project_type)&projects.project_type=eq.billable&start_date=gte.2026-03-01&end_date=lte.2026-03-31
```

## Calculating Revenue & Capacity

The API returns raw data. Here's how to compute derived metrics:

### Capacity (per consultant per month)

```
working_days = weekdays_in_month - holidays_for_country
capacity_hours = working_days × 8
```

### Assigned hours (per month)

Distribute each assignment's hours proportionally across months:

```
overlap_days = days assignment overlaps with month
total_days = assignment end_date - start_date + 1
month_hours = total_hours × (overlap_days / total_days)
```

### Utilization

```
utilization = assigned_hours / capacity_hours × 100
```

### Revenue (precise, from snapshots)

Use the `monthly_snapshots` table for locked months:

```
If is_locked: revenue is frozen (use as-is)
If not locked: revenue = total_hours × bill_rate (may change)
```

### Margin (per project per month)

```
cost = sum(consultant_hours_in_month × consultant.hourly_cost_rate)
margin = monthly_revenue - cost
margin_pct = margin / monthly_revenue × 100
```

## Rate Limits

Supabase free/pro tier: 1000 requests/second. Unlikely to hit this with normal usage.

## Security Notes

- The API key provides **read-only** access to operational data
- Write operations (INSERT/UPDATE/DELETE) return `42501 permission denied`
- Sensitive tables (`user_roles`, `sync_log`) are not exposed to the anon role
- Cost rates (`hourly_cost_rate`) are visible — treat the API key as sensitive
- Do not commit the API key to public repositories
